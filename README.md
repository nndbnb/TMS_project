# Теория многоагентных систем — ЛР1

**Тема:** спецификация и архитектурное проектирование многоагентной системы.
**Задача:** распределение складских перевозок между автономными роботами.

Диспетчер назначает задания, роботы самостоятельно проверяют возможность выполнения,
перевозят груз и возвращаются на базу. Общая зарядная станция имеет ограниченное число мест.
Агенты общаются явными сообщениями с задержкой в один такт. Алгоритмы написаны в проекте.

## Запуск

Нужен **Python 3.11 или новее**. Сторонние библиотеки, `pip` и серверы не требуются.
Команды выполняются из корня репозитория.

```bash
git clone https://github.com/nndbnb/TMS_project.git
cd TMS_project
python -m warehouse
```

В Linux при необходимости заменить `python` на `python3`; в Windows можно использовать `py -3.11`.
В PyCharm выбрать интерпретатор Python 3.11+ и запустить модуль `warehouse` с рабочей папкой проекта.

```bash
# Пошаговый режим: Enter — следующий такт, q — сохранить и выйти
python -m warehouse --step

# Все состояния без остановок
python -m warehouse --verbose

# Конкуренция за одно зарядное место
python -m warehouse --scenario scenarios/charger_queue.json --output output/charger_queue

# Невыполнимые задания по массе и энергии
python -m warehouse --scenario scenarios/infeasible.json --output output/infeasible

# Позднее поступление заданий и мягкие сроки доставки
python -m warehouse --scenario scenarios/delayed.json --output output/delayed

# Проверки
python -m unittest discover -s tests -v
```

После запуска в `output/` появляются `summary.json` (итоги), `trace.jsonl` (сообщения,
действия и состояния каждого такта) и `scenario.json` (входные данные для повторного запуска).
Следующий запуск в ту же папку заменяет эти три файла; разные прогоны сохранять через `--output`.

Код выхода: `0` — прогон завершён, `1` — ошибка входных данных,
`2` — достигнут `--max-ticks` (по умолчанию 1000) или демонстрация остановлена.
Невыполнимое задание — штатный исход со статусом `unassignable`, отдельно от `completed`.

## Границы модели

Склад — прямоугольная сетка без препятствий и столкновений. Каждый рейс начинается на базе
с полным аккумулятором и заканчивается возвращением на базу; после него робот заряжается.
Погрузка и разгрузка занимают по одному такту; движение на клетку расходует единицу энергии.
Ожидание и связь энергию не расходуют. Срок доставки мягкий, просрочка измеряется отдельно.

В ЛР1 реализован **один** механизм распределения: приоритет заданий и выбор подходящего
робота с минимальным избытком грузоподъёмности. Экспериментальное сравнение алгоритмов,
переговоры и диверсионные испытания относятся к ЛР2–ЛР4 и пока не заявляются выполненными.
